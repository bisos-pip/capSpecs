* Overview, Purpose and Context

<<Overview>>

=bisos.capSpecs= adds CBM (Capability Bundle Materialization) facilities for capabilities that are
not implemented in a package of their own but that reside in BISOS. The CBM machinery (=cbmProc.spcs=
leaves, the =cbmProc.control= gate, the =cbm_*= verbs, =sysCbmManage.cs=) is in =bisos.capability=;
this package supplies the CBSs, sboms and assemble steps that a CBM leaf points at.
CBM sits on top of CBS: a leaf holds only a pointer (=capabilityName= + =cbsSpec=).

The capabilities of Stages 2 and 3 are of capabilityType =induct=, in realm =collective=: their leaves
go under =sys/cbm/collective/induct/<capabilityName>/= (in =bro_rawBisos/bro_rawBisosPlatform=).

This activity is foreign-and-lateral to the session that started it (rooted in
=bisos-pip/capability=, where =sysCbmManage.cs= and the CBM machinery were worked on). Findings
about other packages go to AI-Outputs.org; the evidence for this package's stages is in
=bisos-pip/capability/AI-WorkPlan.org= Stage 4 and in AI-Outputs.org (2026-11-04 entries).

* Stage 2: CapSpecs for pltfrmDevelBecome

<<Stage 2>>

Goal: Create the CBM =pltfrmDevelBecome= (leaf =sys/cbm/collective/induct/pltfrmDevelBecome/=, its CBS
and sboms in this package) that, after a rawBisos install, converts the platform into a developer
platform: git from =anon= to =auth=, and pip from PyPI to local (editable) installs.

Precondition, not part of this CBM: =~/.ssh/config= holds the ssh Host alias for the git server (such
as =mb2_github=). That is Stage 3 (=pltfrmDevelCreds=). This CBM only /checks/ the precondition.

Replaces =/bisos/core/bsip/bin/pltfrmDevelBecome.sh=, which predates sboms and gitist. Everything below
was done by hand on 2026-11-04 (see =bisos-pip/capability/AI-WorkPlan.org= Stage 4 and the 2026-11-04
entries of AI-Outputs.org) and has to become idempotent and self-verifying.

What the CBM has to do, in order:
1. Check the precondition: the alias resolves and authenticates (=ssh -T git@<alias>=); stop with a clear
   message if not.
2. Git, anon to auth:
   - the =bxReposRoot= base: =bx-gitReposBases -v 20 --baseDir="/bisos/git/auth/bxRepos"
     --pbdName="bxReposRoot" --vcMode="auth" --gitLabel="<alias>" -i pbdUpdate all=;
   - the repos outside =bisos.common='s registry: =gitLabel=<alias> bxRepos-gitist.pcs -i csCmndEval all=
     (it skips existing clones);
   - the =/bisos/git/bxRepos= symlink pointing to =/bisos/git/auth/bxRepos=.
3. Pip, PyPI to local:
   - the =dev-bisos3= venv: =bisosPyVenvSetup.sh -i pyVenv_DevSetup= (creates it);
   - every =bisos-pip/*/py3/pypiProc.sh= installed editable:
     =pypiProc.sh -i pkgReInstall edit /bisos/venv/py3/dev-bisos3=, as a loop of our own, because the
     =ftoProc.sh= walk of =vis_venvPy3Dev_pipInstalls= visits nothing (nodesList is only =profile=);
   - the pip packages of =rawBisos-sbom.pcs= present, locally if a clone exists, else from PyPI.
4. Verify, and report real failure: =pkgReInstall= exits 0 on failure, and the walker reports =failed=0=
   (g_csMain), so the CBS checks each package itself (=pip list -e=, import, per-package log).

Known problems to handle (from the 2026-11-04 run): =lcnt=, =pycs=, =qmailSvc= and =gnome= do not
install (generated =setup.py= / requirements wrong, or pygobject needs =mesonpy=); =vis_sitePkgsBaseGet=
knows only Python 3.9 and 3.11 (host is 3.13); a clone may exist only under =anon=; running
=pkgReInstall= dirties every repo (=py3/README.rst=, =py3/_description.org=).

* Stage 4: pltfrmDevelUnBecome --- a Fast Switch Between Anon and Devel

<<Stage 4>>

Goal: the CBM =pltfrmDevelUnBecome= (leaf =sys/cbm/collective/induct/pltfrmDevelUnBecome/=) switches a
developer platform back to anon mode, /quickly/, and its own =cbm_unMaterialize= switches back to devel,
just as quickly. Nothing is installed or removed by either: only the mode changes. Needs no credentials.

The decision (2026-11-04, user): =pltfrmDevelUnBecome= is a separate CBM, and it is not the
=cbm_unMaterialize= of =pltfrmDevelBecome=. The two CBMs have different jobs:

| CBM                 | Job                      | Cost                 | Its unMaterialize       |
|---------------------+--------------------------+----------------------+-------------------------|
| pltfrmDevelBecome   | build the devel platform | slow: clones, pip -e | not the way to go anon  |
| pltfrmDevelUnBecome | switch to anon mode      | fast: switch only    | switch back to devel    |

Devel mode is two things (to be pinned in =<<4.2>>=): the =/bisos/git/bxRepos= symlink pointing to
=/bisos/git/auth/bxRepos=, and the =dev-bisos3= venv with the =devbin= scripts being /in use/. Anon mode
is the symlink pointing to =/bisos/git/anon/bxRepos= and the regular =/bisos/venv/py3/bisos3= in use.
=dev-bisos3=, =devbin= and the =auth= clones all stay on disk in both modes.

Assessment of the approach (Claude, for review):
- Good: it makes the mode a toggle, both directions are cheap and repeatable, and the build
  (=pltfrmDevelBecome=, slow, idempotent) is run once. A toggle is also safe: it destroys nothing, so
  uncommitted work in the =auth= clones and the editable installs are never at risk.
- The two edges: (1) =pltfrmDevelBecome= stays the only place that installs; the switch back must not
  silently assume the devel platform is still complete. A cheap drift check on switching to devel is
  needed (are the =auth= clones all there, is every package still editable, did =anon= gain repos).
  (2) Anon and =auth= clones drift apart: =anon= can be weeks behind, so anon mode is not "the same code
  without write access".
- What "in use" means has to be made explicit. Today =/bisos/venv/py3/devbin= and
  =/bisos/venv/py3/dev-bisos3/bin= come /before/ =/bisos/venv/py3/bisos3/bin= on =PATH= (positions 9, 10
  and 11 in an interactive shell on 2026-11-04), so devel mode is "in use" just because those directories
  exist. Removing them is what the first design did; renaming them is not safe (a venv has absolute
  paths: shebangs, =activate=). So the switch has to act on =PATH= (where it is built, and for
  non-interactive users such as CBM subprocesses, sudo and systemd, whose =PATH= is not the shell's).
  The editable installs themselves point at =/bisos/git/auth/...= directly, not through the symlink, so
  flipping the symlink does not break =dev-bisos3=.
- The switch must verify itself: =readlink /bisos/git/bxRepos=, =which aiActivity.cs=, and that
  =from bisos import b= resolves where the mode says it should. =g_csMain= and =pkgReInstall= report
  success on failure, so the CBS checks, it does not trust exit codes.

What it must not do (to be confirmed):
- Delete the =auth= clones, =dev-bisos3= or =devbin=: they hold the devel platform and may hold
  uncommitted work.
- Touch =~/.ssh/config= (Stage 3's, the user's).
- Switch while =sysCbmManage.cs= or a materialization is running (the mode changes which code they run).
